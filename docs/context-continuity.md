# QQ 会话关联与按需原文读取

本次改动针对 reserved2 模式的两个问题：按气泡取历史会使多条回复挤掉原问题；人格中的嘴硬、装傻指令会干扰事实纠正。实现位于 qq-bridge 源码仓库，不修改 DSH 宿主、部署状态或历史日志，也不引入外部记忆插件。

## 分工

- bridge 保留真实消息、引用线索、已展示来信水位和可靠收发信息。
- DSH 根据系统预设理解当前问题、保持目标与约束，必要时使用现有 activeTopic 轻量记忆延续话题。
- bridge 不用关键词猜测用户意图，不生成新的语义摘要，不把模型旧回答提升为事实。

## 快照按问答组选择

`socialV2.context.wakeRecentLimit` 现在表示最近问答组数量，默认仍为 4。每组先提供一条来信，再预览其后的最多四条连续自身发言；总快照仍受 `wakeMaxChars`（默认 6000 个 JSON 字符）限制。先放问题，预算不足时停止该组，避免只留下回答。

新增 `contextInputSeq`：发送记录生成时，最后已展示的连续来信水位。它是输入关联线索，不保证该回复真正指向最后一位发言者；群聊和异步任务尤其不能把它当作确定的因果关系。旧消息没有此字段时，只能按相邻顺序提供历史。

有唯一匹配的文本引用时，`quoteRef` 指向当前会话原文，快照优先补充引用目标及关联来信。相同引用文本匹配多个候选时不生成链接。当前引用文本解析仍受 QQ 的引用格式、昵称与预览长度限制，不代替真实 QQ messageId。

通过 `qq_wait_for_messages` 收到新来信时，也附带最多两组、总计不超过 2000 JSON 字符的 `recent` 预览。关闭 `getRecent` 时不附带。历史预览不授予其他未读消息的已读权限。

## 预览与原文分离

新收发的普通文本消息保存到 `state/context/<摘要>.json`。文件名由会话 key 和当前 agent token 的摘要生成，正文不包含该 token。不同会话和 token 代际独立；正常重启可以恢复，清空/退休会话导致 token 轮换后，旧引用不再从新会话读取。

每个代际保留最近 200 条原文，每条最多 64000 个 UTF-16 码元。超过上限设置 `originalTruncated=true`，不得声称是完整原文。替换的是有界回取缓存，不是永久归档；既有私聊 archive 的格式和上限不变。旧代际文件保留在磁盘，需由管理员按数据保留策略清理；原文缓存不跨代际自动迁移。

写入前使用 bridge 已有的已知 token 脱敏。目录/文件沿用状态文件的受限权限和原子写入；持久化失败记日志，本进程仍可读取缓存。它保存聊天原文，不进行通用的隐私语义识别。

模型预览字段：

| 字段 | 含义 |
| --- | --- |
| `contextRef` | 内部稳定读取标识，形如 `ctx_<uuid>` |
| `textTruncated` | 当前预览省略了原文，不能把它当成全文 |
| `originalChars` | 脱敏后原文长度 |
| `originalTruncated` | 保存的原文本身超过上限，有无法恢复的部分 |
| `quoteRef` | 唯一匹配到的引用目标，可能不存在 |
| `contextInputSeq` | 自身发言生成记录时最后已展示的连续来信水位 |

普通出站长消息预览保留开头和结尾，中间显示省略标记；入站继续保留原有头尾预览，同时标记截断。这里是确定性摘录，不是语义摘要。

这些字段只影响新记录。更新前已截断的缓存不能凭空恢复；工具会明确返回找不到原文，不能把旧预览重命名为全文。语音、拍一拍和表情仍使用原有媒体工具，不承诺由文本原文缓存恢复。

## 按需读取

扩展已有 `qq_get_message_detail`，沿用当前会话 token、模式、白名单和 `getMessageDetail` 开关。不开放文件或终端权限。

```json
{
  "key": "private:<QQ号>",
  "token": "<当前会话令牌>",
  "messageId": "ctx_<消息标识>",
  "full": true,
  "offset": 0,
  "limit": 2000
}
```

`full` 默认为 false，保持旧版 200 字详情预览；全文优先用 `contextRef`，也接受当前缓存已保存的 QQ ID 或本地来信 seq。它们不是归档 seq。

读取结果在 `info` 中返回 `text`、`offset`、`nextOffset`、`totalChars`、`originalChars`、`originalTruncated`。使用 `nextOffset` 继续，直到 null。每段默认 2000，允许 1–4000 码元；为避免拆开 emoji 代理对，必要时一段可多一个码元。不要自行按字符数推算偏移；无效偏移返回 400。

当用户引用旧话、询问摘要未展示的数字/条件，或来信标有 `textTruncated=true` 时，先读取对应原文。`found=false`、`originalTruncated=true` 时说明缺失，不能补猜。`contextRef` 仅用于读取，发送 QQ 引用仍需真实 `messageId`。

### 已读水位

截断的入站预览不再自动授予该消息的完整读取凭证。分段读取必须覆盖原文从头到尾的连续范围，才能推进 `readThroughSeq`；只读尾部、只看控制台、只构建快照都不能推进。凭证仅在内存中保存，重启后需重新读取。超过保存上限的正文不授予完整凭证，应由管理员处理，不能假装读完。

旧版不带 `throughSeq` 的收尾接口仍保留既有兼容语义。新调用必须使用实际返回的水位；该兼容入口不应被用来绕过长文阅读。

## 人格与任务规则

两代 QQ 预设增加理解边界：先保持目标、经历和约束，再选择语气；纠正优先于玩梗；模型旧回答不是用户事实。二代预设补充预览和原文读取协议，并收紧故意答错、已读乱回的许可。默认小鲸鱼角色卡同步修正“不能找补”等冲突表述，保留短句和傲娇语气。

预设源仍在本仓库 `dsh/agent-presets/`，发布时使用的生成文件在 `plugins/qq-agent-presets/presets/`。二者必须由脚本同步：

```sh
node scripts/build-agent-preset-patches.mjs
node scripts/build-agent-preset-patches.mjs --check
```

自定义角色卡不会被自动改写；即使保留旧卡，预设中的理解边界也适用。既有 DSH 会话可能仍带旧系统提示与旧角色，部署后建议在新会话中验证。

## 验证与部署

```sh
npm run test:context
npm run test:token
npm run test:role-card
npm run test:preset-prompt
node scripts/test-agent-preset-patches.mjs
```

测试使用临时状态和模拟 QQ/DSH：覆盖“旅行背景 → 比较请求 → 四个回复气泡 → 引用纠正”、等待期间新消息、原文分段/Unicode、截断已读水位、token 代际隔离与保留上限。测试环境补齐了 bridge 新增依赖的 VM 绑定；提示词往返测试显式构造 CRLF 样本，避免依赖源码文件行尾或段落位置。

这些测试验证数据与协议，不证明模型在每次采样中都能正确理解。实际验收应以新会话重放上述流程，再追问长文中间的数字，确认先回取、后回答；观察是否明确修正用户前提。

2026-10-25 静态与隔离验证：新增上下文测试 10 项通过；完整 `test:audit` 为 32/36 个脚本通过。剩余四个失败也在未修改源码副本中复现：`start.bat` 的既有 LF 行尾不满足 CRLF 检查、缺少 `docs/guides/VOICE.md`、macOS 没有 Windows `chcp`、没有本机 DSH 安装目录供工具名对账。未为消除这些失败而修改启动脚本、补造文档或跳过断言。验证使用固定锁文件依赖及仓库已有的 SnowLuma postinstall 补丁；macOS 临时目录使用规范化的 `/private/tmp`。

当前 Compose 从构建参数指定的 qq-bridge Git ref 构建镜像，修改本源码目录不会自动更新运行容器。后续部署需明确采用包含本改动的源码/ref，重新构建并执行既有 setup-dsh 初始化；本次不修改 Docker/Compose、不重启服务。

本次不替换 DSH 历史压缩器，也不缩短已经进入会话的网页 HTML 或工具参数。原文回取会增加当前步骤的必要输入；它解决可靠获取细节，不能单独保证总 token 量下降。
